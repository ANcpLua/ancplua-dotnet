# Submission Studio 2.3.0 validation

This release implements the 2.2.1 plan by refactoring the existing source,
policy, wizard and bundle modules in place. GitHub/ZIP/folder acquisition,
current official-document retrieval/indexing, source-derived drafts, native
question/response contracts, independent-review adapters, prepared fixes and
version-2 persistence are executable. Host model and question capabilities
remain host adapters, rather than an embedded model service or new MCP server.

The independent forward exercise used the synthetic review-prep ZIP, live
primary documents and an actual separate reviewer agent. It retained four
source-backed official findings and two advice/guidance findings; thirteen host
cases stayed Not run. Export/restore preserved exact source, docs, selections,
plan and raw independent output. Native choices were simulated for this test;
actual widget rendering/selection, target execution, endpoint contact, creator
facts, demo playback and all portal actions were unperformed.

The release check records in `evidence/2.3.0/` describe the final Python,
TypeScript, skill and package checks, their commands and exact scope. Earlier
failed integration observations remain in the exercise archive so repairs can
be traced without turning failed attempts into passes. A second current-source
smoke checks the live docs adapter, while a small public GitHub read checks
transport and commit pinning only. Private GitHub handling uses injected tests.

The historical 2.0.1 self-audit and 2.1/2.2 protocol/host evidence retain their
original target/version scope. No release claims first-pass acceptance,
reviewer time savings, actual directory acceptance or newly verified MCP-host
compatibility without the corresponding observation.

Final checks on 2026-10-16 passed: 77 Python tests (15 preflight, 18 wizard,
39 runtime-v2 and five workflow), Python compilation, skill validation, both
TypeScript syntax checks and the connector kit TypeScript build. The pinned
TypeScript sources/configuration/dependencies match the tested build workspace.
A historical version-1 checkpoint restores with its pause state, prior plan,
execution binding and history retained, while current documentation remains
unverified offline and no new creator confirmation is invented.
