# MSTest Extensions 3.0.0 evaluation

Archive note (3.2.0): the findings below are historical. Local raw artifacts
were removed at the owner's request; retained conversation records identify the
original runs.

Evaluated on 2026-10-17 after the
[3.0.0 release](https://github.com/ANcpLua/mstest-extensions-plugin/releases/tag/v3.0.0).
Four of five scenarios met their recorded checks. The missing-version planning
scenario respected its constraints but did not activate the skill.

## Method

The [case definitions](cases.json) cover implementation, a follow-up, an indirect
request, an unrelated application edit and an unresolved-version boundary. The
implementation uses the existing [prompt](prompt.txt) and [fixture](fixture).
Other fresh conversations receive only their case prompt and an isolated working
directory. No prompt names, invokes, attaches or selects the plugin. The
follow-up continues the implementation conversation without a corrective prompt.
This follows the official [plugin testing guidance](https://developers.openai.com/plugins/deploy/connect-chatgpt).

The host was Codex CLI 0.163.0, using the account's configured `gpt-6.1-sol` model
at `high` reasoning effort. Each invocation used `--no-daemon` and per-process
overrides `features.remote_plugin=true`, `memories.use_memories=false` and
`memories.generate_memories=false`. Global configuration was not edited.
Persisted startup records contain no injected memory summary; observable tool
calls contain no memory-file or previous-session reads. The follow-up intentionally
retains its own implementation conversation.

The account catalog reports 3.0.0 installed and enabled. All 26 installed skill
files match the released source. All 27 uploaded files match account read-back,
and the generated compatibility manifest is synchronized to 3.0.0. The downloaded
GitHub archive matches SHA-256
`f18ffc8190bb57f19a143a5fc8b432016f4ad55cd6e1e5be9ba9042a2c8111e7`.

## Implementation evidence

Independent review of the generated code, normal runner output, structured child
results and discovery checks found:

- `GetTestMethodAttribute` wraps the supplied attribute; `ExecuteAsync` awaits
  and returns its original result array, appending only timing output.
- `dotnet test --project Diagnostics.Tests.csproj --no-ansi --no-progress`
  passed all 8 parent tests. Tests cover asynchronous delegation, result identity,
  failures, attachments, empty arrays, concurrent invocation and real runner behavior.
- The child runner executed all 4 data rows: 3 passed and 1 deliberately failed,
  with expected exit code 2. The original failure message and stack location
  survived, and all rows included elapsed timing and their expected arguments.
- JSON discovery verified all 4 original file, `lineStart` and `lineEnd` values,
  including custom method attributes. No manual Rider click-through was performed.
- SDK pins were unchanged. Both generated projects resolved MSTest.Sdk,
  framework and adapter 4.5.1, MTP 2.5.1 and .NET SDK 10.0.401.

The model corrected three unsuccessful compilation attempts without evaluator
feedback: missing child restore assets, analyzer-required assertion APIs, and
nullable/cancellation diagnostics. It also used standalone builds before its
final test run. The successful outcome does not imply first-attempt compilation
or an optimal verification sequence.

## Findings and limits

The current description emphasizes implementation and migration. Explicit
planning/explanation wording is a candidate improvement for the observed boundary
activation miss; it has not been changed or validated by this release. The failed
case is retained unchanged for a future comparison.

These are single observations on one configured host, not activation rates or
guarantees across models and prompt variants. They do not establish cloud-only
ChatGPT behavior, exhaustive extension compatibility or manual IDE navigation.
The skill and executable assets are unchanged from 1.2.1. Release
[CI](https://github.com/ANcpLua/mstest-extensions-plugin/actions/runs/39030969563)
separately passed both recorded versions, runner policies, hosting and published
Native AOT consumers.

Commands, observable traces, startup audits, generated source and runner artifacts
remain in ignored local `artifacts/release-3.0.0/`. Evaluation prompts and this
report stay outside the installed plugin package.
